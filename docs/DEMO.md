## Scene narration details

### Scene 1 – Architecture (0:00–0:30)

Show `docs/demo/images/01-architecture.svg`.

**Narration:** *"We have four layers: A Vue 3 TypeScript frontend deployed on Vercel. A .NET 10 REST API on Railway that validates Supabase JWTs. A Python FastAPI service on Railway for CV assessment. And Supabase for Postgres and auth."*

---

### Scene 2 – Login (0:30–1:00)

Open `http://localhost:5173/login`. Enter `admin@demo-ats.local` and password. Click Sign in.

**Narration:** *"The frontend calls Supabase Auth, gets a JWT, then immediately calls /api/account/me to load the profile and role. The admin role badge appears in the header."*

---

### Scene 3 – Admin creates customer (1:00–1:45)

Navigate to Admin view. Fill in customer form: email `customer@demo-ats.local`, role Customer, company Nordic Tech AB. Click Create Account.

**Narration:** *"The .NET AdminController receives the request, verifies the caller is admin, then uses the Supabase Auth Admin API to create the auth user. It inserts a matching profile row with role customer."*

---

### Scene 4 – Customer creates job (1:45–2:30)

In Admin view, click Act As for the new customer. Navigate to Dashboard. Click New Job. Enter title "Senior Frontend Engineer" and description. Submit.

**Narration:** *"Admin is now acting as the customer. The frontend sends customerId on every request. The .NET backend scopes all queries to that customer's data."*

---

### Scene 5 – Add candidates (2:30–3:15)

Navigate to Kanban. Click Add Candidate three times:
1. Anna Lund, anna.lund@example.com, LinkedIn URL, paste sample CV text.
2. Erik Berg, erik.berg@example.com, LinkedIn URL.
3. Maria Karlsson, interview stage.

**Narration:** *"Candidates store full profile information including LinkedIn URL and pasted CV text. The CV text is what the AI service uses for assessment."*

---

### Scene 6 – Kanban and filters (3:15–4:00)

In Kanban: select "Senior Frontend Engineer" in the Job dropdown. Type "Erik" in search. Move Erik to Interview using the stage select. Clear filters.

**Narration:** *"The Kanban view calls /api/candidates with customerId, jobId, and search parameters. The backend uses an ILIKE query for name search. Stage moves call PATCH /api/candidates/{id}/stage."*

---

### Scene 7 – AI assessment (4:00–4:40)

Click "🤖 Assess CV" on Anna Lund's card. Wait for result. Show AiAssessmentPanel with score, summary, strengths, concerns, questions, and provider: mock.

**Narration:** *"The .NET API sends candidate and job context to the Python FastAPI service. The mock scorer uses keyword overlap between the job description and CV text. The result is stored in the candidates table and shown immediately."*

---

### Scene 8 – Deploy checklist (4:40–5:00)

Show `railway.toml`, `frontend/vercel.json`, and a code comment from `CandidateCard.vue`.

**Narration:** *"The repository is production-ready: Railway config with health check for the .NET API, Vercel SPA rewrite for Vue Router, and the AI service runs via Procfile. Code comments explain cross-file relationships throughout."*

## Recording checklist

- [ ] `supabase/migrations/0001_init.sql` executed in Supabase SQL editor
- [ ] `supabase/seed/bootstrap_admin.sql` executed with real admin UUID
- [ ] `backend/MiniAts.Api` running locally on port 5000
- [ ] `backend/ai-service` running on port 8001
- [ ] `frontend` running on port 5173
- [ ] Three candidates with CV text added
- [ ] Placeholder images generated (`python scripts/generate-demo-placeholders.py`)
- [ ] Screen resolution: 1280×720 minimum

## Fallback if app is not running

If the app is not running before recording:

1. Run `python scripts/generate-demo-placeholders.py`
2. Record narration over the SVG placeholder screens
3. Clearly state: *"These are placeholder screens. The full implementation code is in the repository and builds with `dotnet build` and `npm run build`."*
